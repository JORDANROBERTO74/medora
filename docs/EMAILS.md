# Emails

All transactional email is sent by **Resend** with **React Email** templates. Supabase's
own mailer is replaced by the `send email` Auth Hook, so nothing goes out from Supabase.

## Templates

| Template | Trigger | File |
| --- | --- | --- |
| Welcome | Successful signup | `src/emails/welcome-email.tsx` |
| Password reset | Forgot password (Supabase hook) | `src/emails/password-reset-email.tsx` |
| Password changed | Password change or reset | `src/emails/password-changed-email.tsx` |

Shared shell: `src/emails/components/email-layout.tsx` (inline styles, Spanish copy).
Sending code: `src/lib/email/send.tsx`; link builders: `src/lib/email/links.ts`.

Preview locally:

```bash
pnpm email   # react-email dev server for src/emails
```

## Flows

- **Signup**: the account is created and the session returned; the welcome email runs in
  `after()` so it never delays or breaks the response.
- **Recovery**: `resetPasswordForEmail` fires the Supabase `send email` hook →
  `POST /api/auth/send-email` verifies the `standardwebhooks` signature, builds
  `${NEXT_PUBLIC_SITE_URL}/auth/confirm?token_hash=…&type=recovery` and sends it with
  Resend. `/auth/confirm` calls `verifyOtp` **server-side**, sets the session and the
  `medora-recovery` cookie, then redirects to `/reset-password`. Because the token is
  consumed on the server, the link works from a different browser or device (PKCE code
  exchanges would not).
- **Password changed**: after `changePassword` / `resetPassword`, an informational email
  is sent via `after()`.

Missing `RESEND_API_KEY` never breaks auth: the send helper logs and skips. Hook failures
return `503` with `retry-after` so Supabase retries.

## Environment

```
RESEND_API_KEY=
EMAIL_FROM=onboarding@resend.dev     # verified domain sender in production
SEND_EMAIL_HOOK_SECRET=v1,whsec_…    # generated by the setup script
NEXT_PUBLIC_SITE_URL=https://medora.vercel.app
```

`EMAIL_FROM` can be `Medora <no-reply@yourdomain>`; Resend requires the domain to be
verified. Without a verified domain, `onboarding@resend.dev` only delivers to the Resend
account owner's address (fine for a smoke test).

## Activation (Supabase project)

Run once, with a personal access token:

```bash
SUPABASE_ACCESS_TOKEN=sbp_... SITE_URL=https://medora.vercel.app node scripts/setup-auth-emails.mjs
```

The script stores the function secrets, enables both Auth hooks, sets Site/Redirect URLs
and writes `SEND_EMAIL_HOOK_SECRET` to `.env.local` (the same value must exist in the
hosting environment). It never prints the secret.

Manual equivalent: Dashboard → Authentication → Hooks → **Send email** →
`https://<app>/api/auth/send-email`; and **Before user created** →
`https://<ref>.supabase.co/functions/v1/before-user-created`; add the matching secrets to
the edge function and to the app env.

**Local development:** the hook needs a public URL, so use a tunnel (e.g. `cloudflared`)
pointing at `http://localhost:3000/api/auth/send-email`, or test recovery against the
deployed app.
